## 3. Реализация Интеграции и Тестирование

### Ключевые Фрагменты Кода (Реализация)
Ключевым элементом стал SQL-запрос, который фильтрует данные по дате. Пример фрагмента кода:

```python
# Фрагмент SQL-запроса, сгенерированный LLM:
cursor.execute('''
    SELECT id, task, priority, created_at FROM tasks 
    WHERE user_id = ? AND created_at >= datetime('now', ? || ' days')
    ORDER BY created_at DESC
''', (user_id, f'-{days}'))
```

Скриншоты работы (тестирование) иллюстрируют корректную работу команды `/history`.

3.1. Тестирование существующего функционала (сохранение логики)
* Проверка команды `/add`: подтверждение, что команда добавления задач работает корректно, и данные записываются в базу.
* Проверка команды `/list`: подтверждение, что логика просмотра и сортировки задач по приоритету не нарушена.

![Генерация кода (Реализация)](/lab_2/93.png)

3.2. Тестирование нового функционала (/history)
* Основной тест: `/history 7` — бот успешно фильтрует базу данных, используя datetime('now', '-7 days'), и выводит список задач за последние 7 дней.
* Проверка крайнего случая: `/history 0` — бот корректно обрабатывает запрос за 0 дней, выводя только задачи, созданные в текущую дату (включая возможные временные метки).
* Проверка валидации (неверный тип): `/history ABC` — реализована проверка ввода; бот возвращает сообщение об ошибке и подсказку по синтаксису.
* Проверка валидации (отрицательное число): `/history -5` — бот блокирует логически неверный отрицательный ввод и предлагает корректный диапазон.
